# SEO 知识资料审核与清理 Skill

`prepare-seo-knowledge-materials` 用于将已经提供到当前工作环境的企业原始资料，整理为可审核、可追溯、最小风险的 SEO 知识库准备包。

它的核心不是“把所有内容改写一遍”，而是形成一份可以继续交接的初筛资产包：

1. 扫描、分类并识别可进入知识库的内容；
2. 复制完全可保留的源文件；
3. 记录需要删除的文件位置，但不在初筛阶段修改复杂文件；
4. 现场提取企业自身的正式知识要点；
5. 将正式资产、待删除、待定和排除内容物理隔离。

> 本 README 面向操作者。Skill 的实际执行规则以 `SKILL.md` 和 `references/` 中的文件为准。

## 一、主要能力

### 1. 多来源资料接入

支持的输入可以是：

- 本地 Word、PDF、PowerPoint、Excel、TXT 和 Markdown 文件；
- JSON、JSONL、YAML、CSV、TSV 或 XML 等结构化导出；
- 用户直接提供的文本；
- 已授权连接器或接口返回的文本、记录或结构化内容。

Skill 不绑定某个接口格式。不同来源会先转换为统一的“资料项”，再进入同一套分类和处理流程。

### 2. 结构化解析和来源定位

- Markdown 按 frontmatter、标题层级、表格、引用块和代码块处理；
- JSON/YAML 保留 `records[12].body` 类型的字段路径；
- CSV/TSV 保留行列位置；
- PDF 保留页码，PPT 保留幻灯片编号，Word 保留章节和段落位置；
- 邮件或聊天导出只在记录边界明确时拆分，不猜测模糊分隔符。

### 3. 严格内容准入

Skill 先按最小可靠语义单元判定 R0–R4，再汇总为整份资料唯一的 A–E 处理类别。两套代码回答的问题不同：R0–R4 表示“这段内容是什么、能否进入知识资产”，A–E 表示“整份资料最终怎么交付”。

| 内容判定 | 含义 |
| --- | --- |
| R0 可保留 | 企业自身的通用、稳定、可公开且有 SEO 价值的知识；不含客户案例、竞品信息、交易信息或保密内容 |
| R1 可抽象 | 来自企业自身流程或能力描述，原文不宜保留，但可以形成不含敏感细节的正式知识要点 |
| R2 必须删除 | 客户、联系人、供应商、询盘、报价、订单、付款、发货、具体项目，以及局部出现的竞品和客户案例内容 |
| R3 整体排除 | 以竞品研究、竞品对比、客户案例、案例复盘、客户评价、合同、NDA、成本利润、客户图纸或专属方案为主体的资料 |
| R4 不确定 | 内容含义、适用范围、证据性质、声明的处理范围或文本本身无法可靠判断 |

| 处理类别 | 动作 |
| --- | --- |
| A | 原始保留，初筛时逐字节复制到正式知识资产 |
| B | 初筛时复制到隔离区，后续仅对副本删除已批准的明确区域 |
| C | 不保留原文，初筛时输出带来源定位、可正式使用的知识要点 |
| D | 无法可靠处理，仅记录原因 |
| E | 排除，不进入正式知识资产 |

整份资料的汇总规则固定为：

- A：所有实质内容均为 R0；
- B：存在 R0，且局部 R2/R3 可以被完整、精确删除，清理后的剩余内容独立满足 R0；
- C：原资料不能保留，但其中至少有一处企业自身的 R1 内容可以形成有用且不含敏感细节的正式知识要点；
- D：R4 导致无法可靠决定或执行；
- E：R3 占主体、没有可用 R0/R1，或资料没有知识价值。竞品或客户案例类 E 项只记录排除原因，不提取派生内容。

### 4. 正式知识要点与排除内容

输出形式不会降低知识等级。企业自身 R1 内容经过忠实总结、归纳或抽象后，形成“正式知识要点”；它不复制原文，但必须保留安全的来源 ID 和精确定位。初筛时即可现场提取该知识要点，直接进入正式企业知识，不需要第二轮审核。

例如，具名客户在某次项目中购买 800 件定制产品，不能被改写为：

- “公司标准 MOQ 是 800 件”；
- “公司所有定制订单都能在某时限内交付”。

这类客户案例内容不能形成正式知识要点，也不能生成待核验问题、研究主题或其他抽象结果。

正式知识要点使用：

```yaml
record_type: knowledge_point
status: approved
importable: true
usable_as_fact: true
```

竞品资料和客户案例统一删除或排除：局部出现时按 R2 从 B 类副本中完整删除；作为资料主体时按 R3/E 整体排除。审核报告只记录安全的来源标签、定位和排除原因，不复述内容，也不生成任何派生观点。

## 二、能力边界

### Skill 会做的事

- 盘点已提供资料并计算本地文件 SHA-256；
- 识别文件或记录类型、可读性和知识价值；
- 标记敏感、内部、交易、竞品和客户案例内容；
- 生成人工审核用的处理计划；
- 在初筛时复制安全原件、复制 B 类待清理副本或提取正式知识要点；
- 记录处理动作、源文件哈希、输出哈希和验证结果。

### Skill 不会做的事

- 不主动连接客户邮箱、获取密码或扩大接口读取范围；
- 不判断客户授权是否合法或足够；
- 不绕过登录、权限、验证码或其他访问限制；
- 不执行 OCR，不从图片推断事实；
- 不将所有原始资料统一重写为一份摘要；
- 不把单次订单、报价或沟通推广为标准价格、MOQ、交期或保证；
- 不自动将内容写入生产知识库；
- 不撰写 SEO 文章，不用外部知识补全企业事实；
- 不直接编辑、覆盖、移动或删除唯一原件。

## 三、调用方式

安装 Skill 后，通过 `$prepare-seo-knowledge-materials` 调用。默认进入初筛模式，不修改源文件。

### 本地文件或目录

在 Codex 中可以通过 `$` 明确调用：

```text
Use $prepare-seo-knowledge-materials to audit D:\ClientMaterials.
For this knowledge-base triage, process only D:\ClientMaterials.
Create the preparation package and stop before cleaning any B item.
```

也可以使用中文：

```text
使用 $prepare-seo-knowledge-materials 初筛 D:\ClientMaterials 中的资料。
本次知识库初筛只处理 D:\ClientMaterials 中的资料。
生成知识库准备包：复制可完整保留的源文件，提取企业正式知识要点，标记 B 类文件的删除位置；不要修改源文件。
```

上面三行可以直接复制使用，只需替换输入路径。第二行是对本次具体范围的明确处理指令，因此可以作为运行范围确认；不要求操作者自报身份，也不需要写“我确认”、手写 YAML 或日期。Skill 会把当前请求记录为确认来源；如果只附了文件却没有明确要求处理哪些资料，或范围表述含糊，会在读取正文前停止并请求补充。该门槛只记录本次允许处理什么，不判断授权是否合法。

### 已导出的接口数据

接口结果已经导出为 JSON、JSONL、CSV、Markdown 或其他结构化文件时，直接把导出文件作为输入：

```text
使用 $prepare-seo-knowledge-materials 初筛 D:\Exports\mail-records.jsonl。
本次知识库初筛只处理 D:\Exports\mail-records.jsonl。
按每条记录建立资料项，保留记录 ID 和 JSON 路径作为来源定位。
生成知识库准备包和初筛清单，不修改原始导出文件。
```

### 已授权接口或连接器

如果当前环境中已经存在可调用且已授权的接口工具或连接器，应在调用中明确指定读取范围、稳定标识和字段含义。例如：

```text
使用 $prepare-seo-knowledge-materials 审核已授权连接器返回的邮件记录。
本次知识库初筛只处理 2026-08-01 至 2026-08-31、文件夹 Knowledge Review 内的返回记录；不要扩展日期、分页范围或读取附件。
使用 message_id 作为记录 ID，etag 作为版本标识，body 作为正文；sender、recipients、subject 和 sent_at 作为敏感元数据。
生成知识库准备包和初筛清单，不执行 B 类删除，也不写入生产知识库。
```

接口模式下，取数和鉴权由上游适配器负责，Skill 只处理已经授权且明确返回的范围。它不会索要账号密码、扩大查询条件、继续访问正文中的链接或自动下载附件。

如果接口结构还不知道，可先这样调用：

```text
使用 $prepare-seo-knowledge-materials 检查这个接口返回结构。
先只识别字段名、数据类型、记录边界、内容字段、敏感元数据字段和版本字段，生成字段映射建议后停止。
字段含义不明确时不要开始内容分类，也不要持久化完整正文。
```

字段映射确认后，再对规范化的资料项执行 R0–R4 判定和 A–E 汇总。如果接口没有 `etag`、版本号或内容哈希，应在同一会话内使用不可变的返回结果完成审核和后续执行批准；否则必须重新取数并重新审核。

## 四、标准使用流程

### 第一阶段：初筛和准备包生成

首次运行生成：

```text
SEO-Knowledge-Triage/<run-id>/
├── knowledge-assets/
│   ├── formal-knowledge/
│   │   ├── 01_原始保留/       # A 类源文件
│   │   ├── 03_提取知识/       # C 类正式知识要点
│   │   └── 04_处理记录/       # 进入准备包的资产记录
│   └── package-manifest.json
├── review-assets/
│   └── 02_B待清理源文件/      # B 类源文件副本，明确不可直接导入
├── review-only/
│   ├── 01_待删除/             # B 类删除位置
│   ├── 02_待定/               # D 类、结构不明
│   └── 03_排除/               # E 类、图片和不处理项
├── inventory.json
├── triage-results.jsonl
├── B类待处理清单.md            # 人工首先查看的 B 类清理方案
├── 初筛清单.md
└── 文件处理报告.md
```

初筛阶段不删页、不删段落、不修改源文件。A 类源文件复制到正式知识目录；B 类源文件可以复制到独立的 `review-assets/02_B待清理源文件/`，但必须标记为待清理且不可直接导入；C 类知识要点和脱敏处理记录进入正式知识目录。B 类删除方案同时写入根目录 `B类待处理清单.md`，机器可读版本写入 `review-only/01_待删除/deletion-review.jsonl`。

如果是未知接口或未知结构化导出，Skill 会先生成字段映射建议。字段含义模糊时，必须等待确认，不会直接分类内容。

### 第二阶段：人工确认和后续清理

操作者需要审核：

- A–E 分类是否正确；
- B 类删除位置是否完整；
- 竞品、客户案例和可重新识别的组合信息是否已完整删除或排除，且没有生成任何派生观点；
- B 类文件具体删除位置是否正确；
- 哪些 B 类删除动作可以执行，哪些应当拒绝或修改；
- B 类清理动作是否可以执行；A/C 资产可以按清单进入后续知识库导入流程。

如果后续要执行 B 类清理，批准时最好明确指定 action ID，例如：

```text
批准 action-0001、action-0002 和 action-0005。
拒绝 action-0003；action-0004 保持待定。
```

“看起来可以”、沉默或先前的概括性请求不算执行批准。

### 第三阶段：可选的 B 类清理和验证

执行前会验证：

- 批准记录是否对应当前处理计划；
- 获批准的 action ID 是否真实存在；
- 本地源文件哈希是否和审核时一致；
- 目标路径是否会覆盖原件；
- 该格式的删除动作是否可靠支持。

任何一项失败，对应动作就不能执行。审核后发生变化的源文件必须重新审核。B 类清理成功后，清理副本进入 `formal-knowledge/02_清理后保留/`，并更新处理记录。

## 六、格式限制

- PDF：V0.1 优先支持整页删除；不使用视觉遮挡假装删除底层文字。
- PPT/PPTX：优先支持整张幻灯片删除，并检查备注和元数据。
- DOCX：只删除可靠定位的段落、章节或表格行；需注意修订、批注和文档属性。
- XLSX：只处理明确工作表或单元格范围，并检查隐藏工作表、行列、批注和外部链接。
- DOC/PPT/XLS：只在有可靠本地转换器时生成临时转换副本；否则归入 D 类。
- 扫描 PDF：本 Skill 不执行 OCR；核心文本只存在图片中时归入 D 类。

如果无法证明禁止内容已从可见文本、底层可提取文本、备注、批注、隐藏结构和元数据中移除，输出不能标记为可导入。

## 七、脚本说明

### 本地资料盘点

```powershell
python scripts/inventory_materials.py D:\ClientMaterials `
  --output D:\Review\inventory.json
```

该脚本只读取文件元数据和字节以计算哈希，不修改源文件。未支持的扩展名也会进入盘点，不会被静默忽略。

### B 类清理前审批验证

```powershell
python scripts/verify_approved_plan.py `
  D:\Review\b-cleanup-plan.json `
  D:\Review\approval-record.json
```

该脚本只用于用户决定继续清理 B 类文件时的审批验证，不会自动修改 Office 或 PDF 文件。实际文档处理必须由合适的格式工具对副本执行。

### 运行测试

```powershell
python -m unittest discover -s tests -v
```

脚本仅使用 Python 标准库，不需要额外安装运行依赖。

## 八、操作与安全建议

- 在读取正文、提取内容或分类前，必须有本次运行级别的范围确认：`confirmed: true`、`confirmed_at`、`declared_scope` 和 `confirmation_source`。操作者只需明确指示本次初筛处理的具体路径、文件或接口范围，这条具体指令即可形成确认；Skill 记录请求来源和时间，不要求自报身份。缺少明确范围时停止，不凭文件已交付、目录可访问或笼统请求推断确认；该门槛只确认处理范围，不判断授权是否合法；
- 审核目录和处理报告也可能包含文件名和内部路径，应按受限资料保管；
- 报告只记录风险类型和位置，不应复制客户姓名、邮箱、报价或竞品细节；
- 下游系统只导入 `knowledge-assets/formal-knowledge/` 中标记为可导入的 A/C 资产；B 类待清理源文件必须等删除并验证后再导入；`review-only/` 永远不能作为导入源；
- 保留 `triage-results.jsonl`、`package-manifest.json` 和 `processing-records.jsonl`，它们共同记录每项资产的来源、处理状态和哈希；
- 如果接口没有稳定版本号或内容哈希，应在同一会话中对不可变资料项完成审核和执行；否则重新审核；
- 图片统一不处理，放入 `review-only/03_排除/` 的图片清单；无法可靠判断时使用 D，不要为了提高“处理成功率”而强行保留、OCR 或推断。

## 十、当前版本的定位

当前版本是可测试的 V0.1，优先保证：

- 输入解耦和来源定位；
- 严格准入与最小风险收口；
- 初筛直接形成 A/C 正式资产并隔离 B，B 类清理另行批准；
- 原件保护和变更检测；
- 竞品和客户案例禁入；
- 正式知识资产与待定/排除内容隔离。

它不追求自动处理所有异常文件，也不保证所有 PDF、PPT 或 Word 复杂版式都能无损修改。在这些场景中，“不强行处理”是预期的安全结果。
